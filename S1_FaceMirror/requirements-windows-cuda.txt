# S1 FaceMirror -- Windows + CUDA 12.8 install requirements
#
# Install with:
#   python -m pip install --upgrade pip
#   pip install -r requirements-windows-cuda.txt
#   # MANDATORY post-install fix -- see "onnxruntime gotcha" below:
#   pip uninstall -y onnxruntime
#   pip install --force-reinstall --no-deps onnxruntime-gpu
#
# The --extra-index-url at the top routes torch to PyTorch's CUDA 12.8 wheels.
# CUDA 12.8 is required for Blackwell GPUs (sm_100/sm_120 -- RTX PRO 2000/4000/
# 5000 Blackwell, RTX 50-series). Older Ampere/Ada/Hopper cards keep working.
# All other packages resolve from PyPI as normal.
#
# Prerequisites on the build/runtime machine:
#   - Python 3.10 (matches the macOS lockfile; pyfaceau requires >=3.10)
#   - NVIDIA driver R570+ (CUDA 12.8 requires R570; older R530 driver only
#     supports CUDA 12.1)
#   - Microsoft Visual C++ Build Tools 2022 (REQUIRED for installing pyfaceau
#     from sdist -- the "falls back to pure Python" claim in upstream README
#     is wrong: setuptools errors at find-compiler step before any fallback
#     can run. Only needed at install time; not at runtime once the
#     PyInstaller bundle is built)
#
# onnxruntime gotcha:
#   pyfaceau transitively requires `onnxruntime>=1.10.0` (CPU). pip resolves
#   this independently of `onnxruntime-gpu` even though they share the same
#   Python module name (`onnxruntime`). Whichever is installed last "wins",
#   and pip's install order tends to put pyfaceau (and its CPU dep) last,
#   shadowing the GPU package. The post-install fix above forces
#   onnxruntime-gpu back. If `ort.get_available_providers()` does not include
#   `CUDAExecutionProvider` after install, you skipped the fix.
#
# Versions are intentionally loose. Lock with `pip freeze` on a known-good
# Windows machine and commit as requirements-windows-cuda.lock when ready.

--extra-index-url https://download.pytorch.org/whl/cu128

# --- Core CUDA-aware stack ---------------------------------------------------
# torch: CUDA 12.8 wheel (filename will be torch-X.Y.Z+cu128-cp310-cp310-win_amd64.whl).
# torch 2.7.0 is the first release with cu128 wheels and Blackwell sm_120 kernels.
torch>=2.7.0

# ONNX Runtime with CUDAExecutionProvider. pymtcnn and pyfaceau both pick this
# up automatically when they detect CUDA is available.
# 1.20+ ships CUDA 12.x wheels by default on PyPI; 1.21+ adds Blackwell support.
onnxruntime-gpu>=1.21.0

# --- FaceMirror dependency stack (PyPI) --------------------------------------
# Windows install reality:
#   pyfhog   -- 0.1.5 fixes the v0.1.3 transposed HOG indexing bug
#               (hog[x][y] -> hog[y][x] in dlib_hog_to_numpy, matching
#               OpenFace 2.2's Face_utils.cpp layout) AND restores Windows
#               wheel publishing (the v0.1.4 release re-enabled dlib's
#               test_for_odr_violations.h sentinels which don't link on
#               MSVC; v0.1.5 wraps them in #ifndef _MSC_VER). Before 0.1.5,
#               Windows users had to use build_pyfhog_windows.ps1 to clone
#               + patch + build from source; that script and its vendored
#               header have been removed in favor of this PyPI dep.
#   pyclnf   -- pure-Python wheel; uses torch for GPU work
#   pymtcnn  -- pure-Python wheel; lazy-imports onnxruntime CUDA backend
#   pyfaceau -- sdist-only; compiles its Cython exts via MSVC. MSVC Build Tools
#               2022 is REQUIRED on Windows (the "falls back to pure Python"
#               claim in earlier docs was incorrect -- setuptools errors out
#               at the find-compiler step before any fallback can run).
#
# pyclnf and pyfaceau pinned to the EXACT macOS reference versions from
# requirements.lock to keep AU classifier model schema and code paths aligned.
pyfhog>=0.1.5
pyclnf==0.3.3
pymtcnn>=1.1.5
pyfaceau>=1.3.14  # 1.3.13 resets OnlineAUCorrection in clear_cache (silent AU=0 after ~40 videos in earlier versions). 1.3.14 fixes the CLNF temporal-state reset (latent since v1.3.8 due to wrong attribute name; corrupts AUs from the second video onward in any sequence). BOTH are mandatory for batch processing.
